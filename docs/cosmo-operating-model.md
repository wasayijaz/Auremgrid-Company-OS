# Cosmo Operating Model

Auremgrid Company OS is shaped around how a retainer studio actually runs, not around a generic chat-over-docs product.

## Four loops

- Money: the client sees a result and stays.
- Work: a request is captured, assigned, produced, reviewed, and shipped.
- Trust: a visible touchpoint keeps the account from going quiet.
- Learning: reusable rules are promoted into playbooks; client-specific rules stay in the client brain.

## Front door

Work cannot start as a Slack message in someone's head. Intake requires three fields:

- what was asked
- which workspace/account it belongs to
- who requested it and when it is needed

## Forced finish line

A work item cannot enter review until Definition of Done is complete:

- mobile responsive
- assets exported
- creative inside the safe zone
- copy spell-checked
- handoff notes written

Internal review must be closed. Abandoned review is a first-class failure, not an invisible stall.

## Client brain

Each workspace has a client brain:

- snapshot
- brand rules
- landing-page rules
- ads rules
- design rules
- email rules
- dos / don'ts
- open loops

The brain is how Cosmo starts work. The evidence layer underneath it is how Cosmo proves a claim.

## Trust signal

Last touchpoint is treated as the leading retention signal. The account brief always returns days since last touchpoint.

## Room to grow

The first adapters are ports, not forks:

- Graphiti for temporal graph search
- Onyx-style connectors for Slack, ClickUp, Drive, and Figma
- RAGFlow / LightRAG for messy document corpora
- Mem0 for subjective preferences only

Auremgrid remains the authority for tenants, ACL, provenance, work state, and audit.
